# 真实硬件验证（Real-Board Validation）

> **当前状态：尚无已验证硬件（截至 2026-11-16）。**
> 本目录是真实打样闭环的证据包脚手架。在第一块板完成下单、焊接并通过上电测试之前，
> 本项目关于「可制造」的表述均为软件层面的自洽检查，不构成实物验证结论。

## 为什么需要这一页

软件内的 ERC/DRC、fab 输出保真测试只能证明「规则自洽」。
生产级结论需要一条实物证据链：同一份冻结的设计文件 → 真实下单 → 真实板 →
限流上电逐项测试 → 缺陷回流为新规则。每块验证过的板在本目录留一个证据包，
并登记到下方「已验证硬件」表。

## 闭环流程（10 步）

1. **选定黄金板**：从 `examples/` 中选一个有代表性的设计作为验证对象（复杂度适中、含电源与高速信号更佳）。
2. **冻结版本**：打 git tag，记录设计文件（netlist / 规格 JSON）与全部 fab 输出的 SHA-256 哈希，写入证据包 `meta.yaml`。
3. **供应链门禁**：按 BOM 逐项核 LCSC 库存（按需求量 3–5 倍安全系数）、生命周期状态与替代料，结果留档。
4. **官方校验留档**：导出的 KiCad 工程用官方 `kicad-cli` 跑 ERC/DRC（JSON 报告 + 退出码），报告入证据包；自研 DRC 只作预检，不作最终裁判。
5. **下单**：记录订单号、板厂、层数/板厚/表面处理等工艺参数、嘉立创规则核对结果（见 `specs/jlcpcb_design_rules.json`，下单前复核当期官网数值）。
6. **收货检验**：拍板面照片，查外观、丝印、关键尺寸与孔位，结果记入检验表。
7. **焊接装配**：记录焊接方式与异常（连锡、虚焊、器件方向错误等）。
8. **限流上电**：用限流电源逐步上电，按测试表逐项记录（静态电流、各电源轨电压、关键信号波形/功能项），每项给通过/失败与实测值。
9. **缺陷回流**：每个实物缺陷必须回流为一条新检查规则、新测试用例或文档修正，并在证据包中互相引用编号。
10. **归档登记**：证据包入仓，在下方表格登记一行；README 的「已验证」表述只能引用本表。

## 证据包结构

每块板一个目录：`boards/<board-name>-<rev>/`

```
meta.yaml            # 板名、版本、冻结 tag、各文件 SHA-256、订单号与工艺参数
erc-drc/             # kicad-cli ERC/DRC JSON 报告
supply-chain.md      # LCSC 库存/生命周期/替代料核查记录
inspection.md        # 收货检验表
bringup.md           # 限流上电逐项测试表（实测值）
photos/              # 板面与上电照片
defects.md           # 缺陷清单与回流去向（规则/测试编号）
```
